# reference-admin

This is a native SvelteKit admin application generated by Metonia Admin. The generated code is
ordinary application code owned by this project; it does not require a Metonia runtime.

> Security notice: authentication and authorization are intentionally deferred. This starter is
> unauthenticated and is not production-secure until you add an application-specific security
> design, session handling, authorization, CSRF policy, audit logging, and rate limiting.

## Generated stack

- Package manager: `bun@1.4.0` (`bun.lock`)
- Svelte: `5.56.10`
- SvelteKit: `2.70.3`
- Deployment adapter: `@sveltejs/adapter-node@5.5.7`
- UI: `shadcn-svelte` with the `zinc` theme and `lucide` icons, installed under `src/lib/client/ui/components`
- Data boundary: `sveltekit-standard`
- Validation: `zod`
- Persistence: `drizzle` with `postgresql` / `generic` / `pg`
- Docker: `disabled`
- Users resource: `enabled`

## Data boundary

This project uses native `+page.server.ts` load functions and form actions. Route modules validate browser input and delegate persistence to `$lib/server`; no parallel REST layer is generated.

## Develop

```sh
bun install

```

## Quality gates

```sh
bun run check
bun run lint
bun run test
bun run build
```

After a successful build, start the adapter-node server with `bun run start`.

## Database workflow

Copy `.env.example` to `.env` and set `DATABASE_URL` to a PostgreSQL connection string. Drizzle
keeps schemas under `src/lib/server/db/schema` and reviewed SQL migrations under `drizzle`.

```sh
bun run db:generate
bun run db:migrate
```

`db:generate` creates SQL from intentional schema changes. Review and commit that SQL, then run
`db:migrate` explicitly for the target environment. The application never migrates implicitly at
server startup.

## Docker

Docker support is disabled; this project contains no Docker-only workflow.

## Architecture

Application dependencies follow `client -> shared <- server`. UI dependencies flow from pages to
views to components, and SvelteKit route files remain thin boundary adapters.

- Browser-safe code: `src/lib/client`
- Server-only implementation: `src/lib/server`
- Runtime-neutral contracts: `src/lib/shared`
- UI composition: `src/lib/client/ui/{components,views,pages}`

Dashboard demonstrates components → views → pages → routes. Users demonstrates shared schemas, server-only persistence, accessible CRUD views/pages, and thin Standard SvelteKit routes.

The resolved configuration is captured as an import-free literal in `metonia-admin.config.ts`.
