# ADR 0004: Generator Composition and Transactional Pipeline

## Status

Accepted.

## Context

Metonia Admin must generate many valid project combinations without creating a Cartesian-product template matrix. The generator also needs to fail clearly and avoid leaving partial projects when a stage fails.

## Decision

Projects are generated by composing recipes:

```text
SvelteKit base
+
Metonia architecture
+
Admin core
+
UI adapter
+
Theme
+
Data pattern
+
Validation
+
ORM
+
Database
+
Docker
+
Resources
```

The pipeline resolves and validates configuration before writing project files, then applies ordered stages. Stage failures must identify the failing stage and avoid leaving partial output in the final target directory. The implementation should use staging and atomic finalization where practical.

Recipes may contribute files, dependencies, configuration, transformations, commands, and checks. They must not become giant ad-hoc shell scripts or duplicate entire templates for each combination.

## Invariants

- No Cartesian template matrix.
- Validate compatibility before writing to the final target.
- Report the failing generation stage clearly.
- Write `metonia-admin.config.ts`, generated `AGENTS.md`, and generated `README.md` from resolved configuration.
- Generated code remains maintainable without the Metonia CLI.
- Package-manager behavior belongs behind package-manager adapters.

## Extension Procedure

To add a capability:

1. Add the capability definition to the shared registry.
2. Add compatibility rules and support status.
3. Add one or more recipes for the files, dependencies, transforms, and checks it contributes.
4. Plug the recipe into the ordered pipeline only where that capability is selected.
5. Add tests for validation, generation, and generated-project quality gates.

To add `metonia-admin add resource products` in the future:

1. Read the existing `metonia-admin.config.ts`.
2. Resolve the current package manager, UI, theme, data pattern, validation, ORM, and database choices.
3. Apply resource recipes under shared, server, client UI, routes, navigation, and tests.
4. Generate Standard or Remote boundary files according to the project's data pattern.

## Consequences

- The generator can support new UI libraries, themes, Valibot, Prisma, MySQL, SQLite, Neon, Supabase, auth, and deployment adapters without multiplying templates.
- The sequence of generation stages becomes a contract and should be changed deliberately.
- Configuration-aware docs and AGENTS files are generated from the same resolved choices as code.
- Partial-output handling is treated as part of the architecture, not cleanup polish.

## Verification Gates

- Verify the current `sv`/SvelteKit project creation mechanism before implementing the base stage.
- Verify package-manager command syntax and lockfile behavior through each adapter.
- Verify stage transaction behavior on Windows and Unix-like filesystems before relying on atomic moves.

## Test Implications

- Unit-test recipe ordering, compatibility validation, file transforms, and package-manager adapters.
- Integration-test generation into temporary directories.
- Add failure-injection tests proving partial output is not left in the final target.
- Generated-project matrix tests must run install, check, test, and build for every stable advertised combination.
